# Common SubZero mistakes

The shortest path to writing compliant code on the first try. If you're
unsure whether something is a violation, check here before the full
checklist — these are the patterns that get guessed wrong most often.

| # | Mistake | Why it happens | Correct approach |
|---|---|---|---|
| 0 | Choosing a component based on its name | Names do not guarantee visual behavior or prop contracts | Verify the installed type declaration or an existing local usage before selecting the component. |
| 0a | Using `DsImage` with `src` | This package's image API requires a source-set prop | Use `srcSet={[{ src, alt }]}` after verifying the installed declaration. |
| 0b | Using `DsSwitch` for a binary slider | `DsSwitch` renders a YES/NO control | Verify the installed API and use `DsToggle` for the binary slider pattern when supported. |
| 0c | Using `sx` color on `DsRemixIcon` | Semantic icon classes can override the style override | Use the component's semantic `color` prop, such as `color="iconActionPrimary"` or `color="iconNegative"`, when available. |
| 0d | Building tabs without checking the composite API | The package may expose a paired tabs composition | Prefer `DsTabs` + `DsTab` after verifying the installed declarations. |
| 1 | Inventing a radius token name like `--ds-radius-circular` or `--ds-radius-pill` | The name sounds right for the visual shape | 10 radius tokens exist total: `zero`, `deepFreeze`, `quickFreeze`, `gelid`, `glacial`, `frostbite`, `bitterCold`, `cool`, `mild`, `pleasant` (max 28px). Full list in `token-reference.md`. For circles/pills beyond that, use a raw value with a comment. |
| 2 | Treating `plasma`, `hot`, `warm` as radius tokens | These names exist as *spacing* tokens and get confused with radius | Always check which token category a name belongs to — spacing and radius namespaces don't share names by convention but can be visually confused. |
| 3 | Hardcoding a hex color instead of a token | Hex is what the design tool (Figma) exports directly | Map every color to the nearest matching `--ds-colour-*` token; only fall back to a raw value with `/* awaiting token */` if genuinely no token matches. |
| 3a | Mapping a Figma hex color to the *visually similar* token instead of the *exact* token | Large Figma context files truncate during grep; grep doesn't find all hex→token declarations. Easy to guess `#165964` looks like `typoPrimary (#282828)` without seeing the exact fallback in the full context. | MANDATORY: Before writing any JSX, extract ALL `var(--sz\/colour\/[name],[hex])` patterns from the full Figma context file into a lookup table. Build a complete `{ [hex]: tokenName }` map and reference ONLY that map during implementation. If a hex appears in the design but not in your parsed map, flag it for review. Never approximate. |
| 4 | Sizing `DsRemixIcon` with `width`/`height` | Habit from sizing `<img>` or `<svg>` elements | `DsRemixIcon` is a font glyph — size with `fontSize` only. |
| 5 | Putting `fontSize`/`fontWeight`/`letterSpacing` in `DsTypography`'s `sx` | Feels natural to "just style the text directly" | Use the `variant` prop — it controls all of these together. `sx` on `DsTypography` should contain `color` only. |
| 6 | Giving `DsTypography` a `flex`/`display`/layout prop in `sx` | The text needs to participate in a flex layout | Wrap it in a `DsBox` and put layout props there; `DsTypography` carries `color` only. |
| 7 | Using `DsContainer` for a wide table or full-bleed section | `DsContainer` sounds like the generic "wrapper" component | `DsContainer` constrains width (~584px). Use `DsBox` with `width: '100%'` for full-width content; reserve `DsContainer` for genuinely constrained content like forms. |
| 8 | Hardcoding a `boxShadow` value | Easiest way to match a Figma shadow visually | Map to an elevation token (`--ds-elevation-0` through `--ds-elevation-24`, plus `--ds-elevation--1` for inset). Never hand-write shadow CSS. |
| 9 | Leaving a fallback value on a converted token, e.g. `var(--ds-spacing-bitterCold, 16px)` | Fallbacks feel "safer" | Never keep a fallback after converting from `--sz-*` — it silently reintroduces the old hardcoded value as a backup path. |
| 10 | Approximating to the *nearest* token when the exact pixel value doesn't match | Wanting to avoid an "awaiting token" comment | Only use a token if the value matches exactly. An approximate match silently corrupts the spacing/radius scale project-wide. Use the raw value with a comment instead. |
| 11 | Building a custom slider/dropdown/modal from scratch | Assuming the DS doesn't have one, or not checking first | Check available components first: `DsSlider`, `DsModal`, `DsDialog`, `DsAutocomplete`, `DsDatePicker`, `DsFileUploader`, `DsTable`, `DsPagination`, `DsTabs`. Ask before building custom if truly missing. |
| 12 | Adding `'&:hover'`/`'&:focus'` overrides in `sx` | Wanting a specific hover effect | Trust the component's built-in interaction states. If the design genuinely needs a different state style, that's a DS component API question, not an sx override. |
| 13 | Manual `useState` for `isLoading` alongside an existing service-tracking mechanism | Habit from non-Redux projects | If the project has automatic loading-state tracking (e.g. a `ServiceTracker` selector), use that — don't duplicate it with local state. |
| 14 | Direct `fetch()`/`axios` calls instead of the project's HTTP client convention | Generic React habit | Check the project's established HTTP client (e.g. `@am92/web-http` via a configured instance) and use that exclusively. |
| 15 | Transforming/filtering API response data inside the service layer | Feels efficient to shape the data close to the source | Services return raw API responses unchanged. Transformation belongs in selectors or the consuming component/hook. |
| 16 | Constructing a color token name algorithmically from a group prefix (e.g. `neutralNeutral1`, `typographyDisabled`, `iconIconNegative`) | Concatenating the group name with the key using a formula | Token names do **not** double the category prefix. `neutral1` not `neutralNeutral1`. `typoDisabled` not `typographyDisabled`. `iconNegative` not `iconIconNegative`. Always read the exact key from `token-reference.md`; never construct it from a pattern. |
| 17 | Adding `direction='column'` to `DsStack` | Column looks like an explicit setting that should be stated | `DsStack` defaults to `direction='column'`. Setting it explicitly is a no-op and a validation violation. Only set `direction` when you need `'row'` or a responsive object. |
| 18 | Using a bare number for `DsStack` gap (`<DsStack gap={8}>` or `sx={{ gap: 16 }}`) | MUI supports numeric gap which maps to theme spacing | `DsStack` gap must be a token string in `sx`: `sx={{ gap: 'var(--ds-spacing-glacial)' }}`. A bare number bypasses the DS token system. |
| 19 | `overflow: 'hidden'` or FIXED 24px height on a chat bubble | Looks tidy in the empty state; long copy is cropped mid-sentence | Hug height; wrap with `minWidth: 0` + fill parent. `overflow: 'hidden'` only on designed scroll regions. |
| 20 | Composer FIXED height shorter than `DsTextField` (or leftover label slot) | Labelled field still reserves `label_wrapper` (~24px); composer set to 24 or 80 while the field is 76 | Omit the chat label so the field hugs ~44px; composer hugs field + send + padding and pins to the bottom. Children must fully paint. |
| 21 | Body/consent text at measured unwrapped width (482px, 494–785px) | `WIDTH_AND_HEIGHT` / FIXED width from Figma export | Instance/text FILL the parent; wrap. No TEXT wider than the parent content box. |
| 22 | Only restyling layers named “AI turn” / first bubble | Later screens use unnamed frames | Match bubbles by structure (container + wrapping body text in the thread), not only by name. |
| 23 | Open `DsSelect` / suggestion list in a 375 chat column | Default expanded variant from the library | Closed field; never let the menu eat the composer. |
